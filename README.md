# Trading-Analysis

This repository just for my own coding trading workspace.

## FX trend-following research: cycle 3 (pre-registered, NautilusTrader, 5 pairs, 2019-12 → 2023-12)

**Verdict: no strategy passes.**

* All 7 pre-registered hypotheses failed **Stage 1**, the mandate's walk-forward gates on the development
  period.
* None became eligible for **Stage 2**, so the **2023 holdout was never loaded** and stays clean for future
  research.
* No pull request was opened; one is opened only for a hypothesis that passes both stages.

### How bias and data mining were ruled out

About half of the extended data (2020-11 → 2022-12) had already been mined in cycle 2, so this cycle does
not adapt to results. Everything is fixed in [`PREREGISTRATION.md`](PREREGISTRATION.md), which was committed
and pushed (`e6cabfa`) **before the first backtest on the new data**:

* **Fixed hypotheses.** The 7 cycle-2 hypotheses are copied byte for byte from their commits into
  `hypotheses/`. H1–H4 only get an appended shim so their per-pair signal functions accept the 5-pair dict.
  No new ideas and no edits after results; each file's code fingerprint is published in advance.
* **Fixed order.** H1 → H7, run regardless of outcomes. The harness refuses any other order.
* **Split.**
  * Development = 2019-12-02 → 2022-12-30 (3.08 years; meets the original ≥ 3-year rule).
  * Holdout = 2023, **locked**: Stage-1 runs load no bar at or after 2023-01-01 UTC, and a test asserts it
    on every run.
* **Holdout rules.** Only a hypothesis with a logged Stage-1 PASS under the same code fingerprint can use the
  holdout, **exactly once**. The harness enforces both, and both refusals were tested before the runs.

### What the results mean

1. **Nothing is close.** The best candidate, H2, reached OOS Sharpe 0.63 against 1.5. With 2.1
   out-of-sample years the standard error of an annualised Sharpe is about 0.69, so 0.63 is 0.9 SE from
   zero. The best of 7 pure-noise strategies would be expected at about 0.93. The results are consistent
   with **no exploitable edge**.
2. **Cycle 2's best result was luck.** Cycle 2's Trial 1 (0.66 on 2021-07 → 2022-12) is H1 here. With a
   year more of in-sample history and the full development period it scores −0.16.
3. **Split results swing randomly.** Every hypothesis has splits between about −3 and +3 Sharpe, and good
   in-sample windows do not predict good out-of-sample ones.
4. **Costs matter.** Your broker's spreads (1.5–2.0 pips median) plus 0.5 pip slippage per fill cost about
   2.5–3.0 pips per round trip. That is the same size as the gross edge per trade these hourly signals find.
5. **Loosening the gates or iterating further on this data would be data mining.** The gates were not
   changed.

### What could legitimately change the outcome

* **Lower costs.** An ECN / raw-spread account (≈ 0.1–0.3 pip spread plus commission) cuts friction
  several-fold. It must be modelled from that account's real data, not assumed.
* **More history as a new development set.** For example, MT5 M15 from 2010–2019, keeping 2023 as the
  untouched holdout.
* **A broader universe.** More pairs and crosses (AUD, NZD, CHF, …) for diversification.
* **A slower horizon (daily trends).** This needs a mandate change, because the 100 trades/year gate is hard
  to meet at daily frequency with 5 pairs.

Any new idea should be pre-registered the same way before it touches data. The 2023 holdout is still unused
and available for exactly that.

### Engine and execution model (unchanged from cycle 2)

* **Data.** MT5 server time is `Europe/Athens` and is converted to UTC. Signals use hourly MID bars published
  at their close.
* **Execution quotes.** Each hour has quotes at open + 1 ms and at close − 1 ms, built as
  `bid/ask = mid ∓ (max(spread, 1 pip)/2 + 0.5 pip)`.
* **Timing.** A 1 ns order latency means every order fills at the next hour's open quote.
* **Venue.** Nautilus SIM venue, NETTING, USD margin account, zero fees (all costs are in the quotes).
* **Nautilus pitfall.** `BacktestEngine.reset()` clears the FX conversion table, so JPY/CAD P&L silently
  never reaches the USD balance. This is worked around in `Market.run()` and guarded by a test.
* **Risk.** Volatility-targeted sizing: `units = NAV·risk% / (k·ATR·quote→USD)`, whole 1,000-unit lots,
  10× leverage cap per position. Portfolio circuit breakers: a daily loss ≥ 2.5 % → flat for 24 h; a
  drawdown ≥ 10 % → permanent halt.

Each hypothesis's formulas are in the docstring at the top of its file in `hypotheses/`. The families are:

* **Shock momentum (H1, H2, H4, H7).**
  * `Shock_t = sign(C_t − C_{t−1})·1[TR_t > k·ATR_{t−1}]`.
  * Enter in the shock's direction; chandelier stop `S = max_d(S, C − d·m·ATR)`; reverse on an opposite
    shock.
* **Donchian breakout (H3).** Long or short when the close breaks the prior N-bar high or low; chandelier
  stop; stop-and-reverse.
* **Currency strength (H5, H6).**
  * `m_p = ln(C_t/C_{t−L}) / (ATR/C·√L)`, `S_c = mean_p(±m_p)`, `z_p = S_base − S_quote`.
  * H5 enters on zero-crosses of z; H6 enters when |z| > h and exits on the return through 0.
